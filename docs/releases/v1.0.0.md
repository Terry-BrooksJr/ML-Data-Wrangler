# Lasso v1.0.0

**Lasso v1.0.0 is the first production release.** It takes everything from the
v0.9.9 pre-release and adds what was needed to use Lasso day to day:

- a way to **compare engine configurations** before switching;
- a way to **turn judged answers into training data**;
- a tighter **link between Lasso and Zendesk**;
- a **cleaner codebase** to build on.

Lasso is a desktop app for Learnosity Support's Zendesk ticket data. It does
four jobs:

- **Ingest:** reshapes Zendesk exports and stores them in MongoDB.
- **Topic modelling:** finds themes with LDA and BERTopic.
- **Tag normalization:** consolidates synonymous tags.
- **Triage:** a Decision Engine recommends one action per ticket.

Lasso never writes to Zendesk itself.

## Highlights

- **A/B testing:** classify the same sample of tickets with two engine configurations, such as two models, two effort levels or a decision model, and choose between their answers **blind**. Each answer shows its cost. Verdicts are saved onto the tickets. #61
- **Training-data export:** export reviews marked correct, plus A/B verdicts, as **fine-tuning JSONL** or **few-shot Markdown** examples. Corrections from the misclassification log can be included. #70
- **Zendesk links:** **View on Zendesk** opens the ticket in Zendesk's agent workspace. **Review Added to Zendesk** records that a review was copied into the ticket. #69, #71
- **Themes inside an outcome:** train BERTopic on chosen Zendesk outcomes, such as Client Education, and export a topic list ready for curation. #60
- **Leadership routing:** escalations are routed to a leader based on the ticket's assignee. A review is dropped if the ticket is reassigned while it's being classified. #59
- **NumPy 2 stack:** moved to spaCy 3.8, thinc 8.3 and SciPy 1.15. #67

## What's new since v0.9.9

### Decision Engine
- **A/B test two configurations** (**A/B Test…** on the Decision Engine tab, or `python -m decision_engine.ab_test`). #61
  - **Setting up a test:** pick a sample of tickets and two configurations. Lasso estimates how many calls the test will make before running anything.
  - **Saving and resuming:** each ticket is captured as the engines saw it, and every answer is saved as it arrives. An interrupted test resumes without paying for calls that already finished. Calls that failed are retried up to three times. Answers from the last 24 hours can be reused instead of called again.
  - **Blind review:** the two answers appear in random order, and you record which is better (or a tie). Two people can't overwrite each other's verdicts.
  - **Cost:** every answer shows its cost. That's the amount Cheaper Inference billed where the reply reports it, or an estimate from live prices otherwise. You can correct any price before a test starts.
  - **When every ticket has a verdict,** the test is finalized: verdicts are copied to each ticket's `ab_test_verdicts`, and the bulky working data is removed.
  - **Export:** any test exports to CSV or JSON.
- **Decision models:** models Cheaper Inference serves through `/v1/decisions` (such as `jev-1.13.0`) can be used for classification in A/B tests. Lasso recognizes them from the model list, or learns from the first refusal. #61
- **Export Training Data…:** saves judged answers as examples for training a model. #70
  - **JSONL for fine-tuning.** Each example is the ticket as the engine saw it, paired with the answer that was judged correct.
  - **Markdown for few-shot prompting.** It can also include corrections from the misclassification log.
  - **Which examples:** by default, only examples from the current prompt version are exported. Options include older prompts, require the exact original input, or include every correction.
  - **Leaving examples out:** tickets whose history can't be reconstructed, or whose verdict is ambiguous, are left out, and the summary says how many.
  - **Writing the files:** they're written atomically, and an interrupted export is rolled back on the next run.
- **Review Added to Zendesk:** a new ticket field, `Review Added to Zendesk?`, is false until you mark it. #71
  - **The button** sits next to View on Zendesk and asks you to confirm first.
  - **The review detail** shows Yes or No.
  - **Once a ticket is marked,** the button is disabled for it.
- **Leadership escalations:** the leader to notify is chosen from the ticket's assignee, using a shared leadership roster. The prompt and the code checks use the same roster. #59
- **Reassignment-safe reviews:** if a ticket changes owner while it's being classified, the review isn't saved. The ticket stays in the queue for its new owner. #59
- **Fix:** after an action that refreshes the list, the review detail and buttons now update for the row that stays selected. #71

### Topic modelling
- **BERTopic by outcome:** **Train BERTopic Model…** lists every Zendesk outcome with its ticket count. Untick outcomes to train on the rest only. The run records which outcomes it used. #60
- **Richer topics:** each topic records its outcome counts and the five tickets nearest its centre. No ticket text is saved with a run. #60
- **Export Topic List…** writes one row per topic: its size, outcomes, top words and example tickets with their subjects. Blank `proposed_name` and `decision` columns are left for curating a reporting list. #60
- **Custom fields by ID:** the ticket outcome and request type are read by their Zendesk field IDs (27219391 and 27124341), not by their position in the export. #60

### App
- **View on Zendesk** on the Decision Engine tab, in the Weekly Review and in the A/B test's blind review. It opens `https://learnositysupport.zendesk.com/agent/tickets/<id>` in a new browser window. #69
- **New settings:** `AB_TEST_COLLECTION`, `AB_RESULT_COLLECTION` and `DECISION_MODELS`, all optional, with checks that collection names don't clash. #61

### CI, packaging and dependencies
- **Release builds:** pushing a `v*` tag builds the macOS package, publishes it, then installs and launches it on a fresh runner. #58
- **CI:** tests and the dependency check no longer wait for lint, and superseded runs are cancelled. #58
- **NumPy 2 migration:** #67
  - **New versions:** spaCy 3.8 (`en_core_web_lg` 3.8.0), thinc 8.3, SciPy 1.15 and NumPy 2.2.
  - **Fix:** a NumPy 2 change stopped LDA runs from saving to MongoDB; it's fixed.
- **Dependency updates:** smart-open 8.0.4, httpcore2 2.14.0, langchain-core 1.6.12, langchain-protocol 0.0.20, and `actions/upload-artifact` / `download-artifact` v7. #54, #62–#65
- **Cleanup:** `DISCOVERY_NOTES.md` and the unused `Dockerfile` were removed. #59

## Upgrading from v0.9.9

- **Reinstall dependencies:** run `uv sync`. The NumPy 2 move replaces spaCy, its English model and SciPy, and an older environment won't import.
- **Retrain topic models where you can:** the new spaCy model lemmatizes a few words differently (for example *teachers → teacher*, *data → datum*). In testing, 4 of 113 tokens changed.
  - **Saved runs** record their spaCy version, so runs from v0.9.9 aren't reused as if they were identical.
  - **Assigning topics with an older LDA model** still works, but may drift slightly.
- **Backfill the new ticket field:** this adds `Review Added to Zendesk?` (false) to tickets stored before v1.0.0. New tickets get it automatically. It's safe to re-run, and it has already been run on the production `tickets` collection. From `src/`:

  ```bash
  uv run python -m decision_engine.zendesk_status
  ```
- **Create the A/B collections:** `ab_tests` and `ab_results` are used if you run A/B tests. MongoDB creates them on first use, along with their indexes.
- **Command-line paths changed:** modules now live in packages under `src/`, such as `core/`, `topics/`, `tags/` and `ui/`. Commands include the package name: #72
  - `python -m model_storage` → `python -m core.model_storage`
  - `python -m embeddings` → `python -m embedding.embeddings`
  - `python -m embedding_eval` → `python -m embedding.embedding_eval`
  - `python -m bertopic_model` → `python -m topics.bertopic_model`
  - `python -m tag_normalizer` → `python -m tags.tag_normalizer`

  The `decision_engine.*` commands are unchanged. Scripts that import Lasso modules need the new paths, e.g. `from core.wrangler import DataWrangler`.

## Known issues

- **Tag Normalizer:**
  - Language-model runs still can't be saved with **Save Run**. Use **Export Mapping** to keep them.
  - The embedding modes can still group `intent…` tags with free-form ones.
- **Zendesk retag scripts** have only been tested against a simulated Zendesk.
- **macOS builds aren't notarized:** they're ad-hoc signed, so Gatekeeper blocks them on other Macs until they're notarized, or opened with right-click > Open.
- **LDA training is slow on macOS:** each training worker re-imports the app.
- **Chart files aren't gitignored:** `coherence.png` and `lda_model.html` are written to the launch directory.
- **Lint is still report-only in CI.**
- **Unconfirmed engine settings:** the Decision Engine's default model ID and some open items are still unconfirmed (see *Known gaps* in the README). Set **Primary model** explicitly.
